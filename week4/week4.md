# 4주차 카메라·투영 관찰 과제 보고서

> 제출 전 확인: 이 작업 폴더는 GitHub 저장소에 연결되어 있지 않아 공개 Pages 주소와 Git 커밋 기록을 만들지 못했다. 기본 버전 8개 과제의 실제 관찰 기록과 개선 전후의 사람 대상 측정도 아직 없다. 아래 `직접 기록` 칸은 실행해 관찰한 뒤 채운다. 브라우저로 확인한 기능 검증 결과와 사람의 관찰 결과는 구분했다.

## 1. 실행 주소와 조작

| 버전 | 로컬 확인 주소 | GitHub Pages 주소 |
|---|---|---|
| 기본 버전 | `http://localhost:8000/week4/baseline/` | https://kimye520-collab.github.io/cg-2026-solar/week4/baseline/ |
| 개선 버전 | `http://localhost:8000/week4/improved/` | https://kimye520-collab.github.io/cg-2026-solar/week4/improved/ |

로컬에서는 저장소 루트에서 `python -m http.server 8000`을 실행한다. 공개 주소는 GitHub Pages에서 실제 배포된 주소를 확인했다.

개선본은 관찰 목록의 지점을 누르면 해당 명판의 정면에 초점을 맞춘다. P1~P6는 원근 투영을 유지한다. O1을 선택하면 +z 쪽 전면에서, O2는 +x 쪽 오른쪽 측면에서 직교 투영으로 비교한다. O1·O2의 초기 거리는 모두 10 m, 직교 half-height는 3 m로 같으며 휠로 배율을 조절할 수 있다. 비교 과제 재선택은 같은 기준 방향과 배율을 복원한다. 드래그는 회전, Shift+드래그 또는 오른쪽 버튼 드래그는 평행 이동, 휠은 거리·직교 배율 조절이다. 전체 보기 버튼 또는 Home 키는 처음 카메라와 모델 표시 상태로 돌아간다.

각 항목은 실제 표지·구조를 확인한 후에만 `관찰 완료`를 체크한다. 완료 수는 0/8부터 표시된다. O1/O2에서 비교와 관계없는 구조·설비를 숨기며, 상태 문구로 알리고 다른 관찰 항목이나 전체 보기를 선택하면 복원한다.

## 2. 사용자, 목표, 대안 선택

사용자 가정: 이 시설을 처음 보는 점검자가 6개 표지의 내용을 주변 설비와 연결해 확인하고, 두 구조 비교를 마친다. 우선 목표는 작은 표지를 찾고 읽는 조작을 줄이는 것, 그리고 이미 확인한 항목과 비교 과제의 기준 시점을 분명히 하는 것이다.

대안 스케치 두 가지는 [설계 대안 스케치](images/sketch-alternatives.svg)에 있다.

| 대안 | 장점 | 단점 |
|---|---|---|
| A. 전체·전면·측면·상면 4분할 | 여러 방향과 전체 구조를 동시에 비교 | 각 뷰가 작아 작은 글씨를 읽기 어렵고 각 뷰의 입력 방식도 복잡해짐 |
| B. 한 번에 한 관찰 지점으로 이동 (선택) | 상세 뷰포트를 모두 활용하고 목표별 시점으로 바로 이동 | 전체 맥락을 잠시 잃을 수 있어 진행 표시와 전체 복귀가 필요 |

단일 상세 화면을 기본으로 선택하고 완료 체크·전체 보기 복귀를 결합했다. O1/O2만 공통 배율의 직교 비교로 바꿨고, 겹쳐 가리는 모델 부분을 일시적으로 숨겨 기준을 읽기 쉽게 했다. 모델 데이터와 표지 내용·크기는 바꾸지 않았다.

## 4. 카메라·투영 구현

코드 변경은 [d04-inspection-student.js](improved/d04-inspection-student.js), [d04-inspection-controls.js](improved/d04-inspection-controls.js), [index.html](improved/index.html)에 있다. 공용 렌더러의 `drawView`를 사용하고, 제공 모델의 POI·비교 데이터로 목적지를 만든다.

- 표지 관찰: `target`은 명판의 지정 위치, `eye`는 명판의 `yaw` 방향으로 그 위치에서 떨어뜨린다. `up`은 월드 +y 방향이다. 거리 초기값은 표지 높이 `h`와 수직 FOV `θ`를 이용해 `h / (2 tan(θ/2) × 0.42)`로 계산하고 0.45~2.8 m 범위로 제한한다. 작은 명판은 가까이, 큰 안내판은 멀리에서 보도록 하며, 사용자는 이후 휠·드래그로 조정한다.
- O1: `target`은 제공된 비교 중심, `eye`는 +z 쪽 10 m, `up`은 +y이다. 따라서 화면 가로축은 월드 x와 나란한 전면 뷰다.
- O2: `target`은 제공된 비교 중심, `eye`는 +x 쪽 10 m, `up`은 +y이다. 화면 가로축은 월드 z와 나란하므로 앞쪽(+z) 끝을 비교할 수 있다.
- O1/O2: 직교 half-height 3 m를 공통 초기값으로 사용한다. 두 대상을 같은 배율로 비교하고 휠 배율 조정 뒤 과제를 다시 선택하면 기준 배율로 초기화한다. 원근 투영은 명판 읽기와 주변 구조 관찰에 유지한다.
- 클리핑: 렌더러의 기본 near/far는 각각 0.02 m와 180 m다. 최소 명판 관찰 거리도 near보다 크도록 제한한다. 이는 가림과는 별개이므로, 비교 뷰에서는 숨김 상태를 안내하고 복원 조작을 제공한다.
- 화면 비율: 뷰포트 전체를 사용하며 기존 렌더러가 실제 캔버스 종횡비로 원근·직교 투영을 계산한다. 분할 뷰는 구현하지 않았다.

직교 비교 캡처: [O1 전면](images/improved-O1.png), [O2 측면](images/improved-O2.png). 표지 집중 관찰 예: [P3 제어함](images/improved-P3.png).

## 5. 검증 및 개선 전후 비교

### 브라우저 기능 검증

2026-09-30 로컬 브라우저에서 개선본을 실행해 확인했다. 제공 모델의 POI 6개와 비교 2개, 총 8개 목록이 유지됐다. 각 항목을 선택했을 때 회전 중심이 해당 제공 좌표와 일치했다. P1~P6은 명판 방향을 향하고, O1은 eye가 target의 +z 쪽, O2는 +x 쪽에 위치했으며 두 비교 모두 같은 10 m 초기 거리를 사용했다. O1/O2에서 직교 렌더링과 모델 그룹 숨김이 켜지고, 전체 보기 또는 다른 관찰 항목 선택 후 모델이 복원되는 것을 확인했다. 완료 표시 수는 실제 항목 관찰 없이 임의로 올리지 않았다.

### 동일한 8개 과제의 사용자 비교 기록

기본·개선 버전에서 같은 기기, 같은 창 크기, 같은 입력 장치로 전체 보기부터 시작해 직접 관찰한 뒤 기록한다. 개선본의 체크는 사용자의 확인 기록이지 정답 판정 기능은 아니다.

| 비교 항목 | 기본 버전 | 개선 버전 | 해석 |
|---|---|---|---|
| 관찰 완료 수 | 직접 측정: __/8 | 직접 측정: __/8 | 실패·누락 기록 포함 |
| 전체 관찰 시간 | 직접 측정: __초 | 직접 측정: __초 | 목록 확인부터 전체 복귀까지 |
| 조작 부담 | 직접 기록 | 직접 기록 | 기본 카운터는 드래그 시작·휠·키·Home 집계. 개선본의 항목 클릭·체크도 별도 기록 |
| O1 높이·폭 | 원근 트랙볼 캡처·판단을 기록 | [O1 캡처](images/improved-O1.png)와 판단을 기록 | 직교 뷰 기준으로 같은 화면 배율에서 비교 |
| O2 돌출 | 원근 트랙볼 캡처·판단을 기록 | [O2 캡처](images/improved-O2.png)와 판단을 기록 | 측면 직교 뷰에서 z 방향 끝을 비교 |
| 새 불편 | 해당 없음 | 직접 기록 | 예: 숨긴 구조의 공간 맥락 상실, 재선택 필요 |

개선 후 기대만으로 성공을 주장하지 않는다. 측정은 아직 수행되지 않았고, 반복 시 빠른 학습 효과와 기기별 휠 이벤트 차이를 한계로 함께 기록한다.

### 수정 반복 기록

직교 뷰를 처음 확인했을 때 건물의 난간·층 구조가 비교 대상을 가렸다. 이에 O1/O2에서 비교와 무관한 모델 그룹을 임시 숨기도록 수정하고, 화면 문구·복원 조작을 추가했다. 최종 [O1](images/improved-O1.png)·[O2](images/improved-O2.png) 캡처에서 두 대상이 겹치는 구조 없이 보이는 것과 전체 보기 후 복원을 확인했다. 숨김 때문에 전체 건물 맥락이 줄어드는 점은 남은 한계다.

## 6. AI 제안 검토, 배포, 제출 전 점검

AI가 제안한 대상별 카메라 이동은 채택했다. 다만 비교 과제를 일반 표지처럼 원근 이동만 시키는 것으로 충분하지 않다고 판단해, 과제 지침의 전면·측면 직교 요구에 맞게 별도 투영을 추가했다. 첫 비교 화면에서 주변 구조가 가리는 것도 실행 화면으로 확인한 뒤 임시 숨김과 복귀 상태 안내를 보완했다.

- [x] 실제 GitHub Pages 주소를 위 표에 입력하고 공개된 페이지가 실행되는지 확인
- [ ] 기본 버전 P1~P6/O1/O2 관찰 표와 불편 3개 이상을 캡처와 함께 작성
- [ ] 같은 조건으로 개선 전후 측정 표 작성
- [ ] 다른 화면 크기에서도 모델이 찌그러지지 않는지 직접 확인

현재 작업 폴더는 Git 저장소가 아니며 원격 저장소 정보도 없어 Pages 배포, 공개 주소, commit 기록은 이 작업에서 만들지 않았다. 위 항목은 해당 저장소에서 제출 전에 완료한다.
